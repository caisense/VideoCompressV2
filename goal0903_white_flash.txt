======================================================================
1. 已确认的根因和证据
======================================================================

当前问题位于：

    tools/full_frame_enhancer.py
    FullFrameEnhancer._postprocess_native()

当前逻辑根据每一帧的全局 min/max 动态猜测模型输出范围：

    if minimum < 0 and maximum <= 1.1:
        (array + 1) * 127.5
    elif maximum <= 1.5:
        array * 255

RealESRGAN 的输出语义是以 [0,1] 为基准，但卷积输出可能轻微越界，
例如出现少量负值或大于 1 的像素。

因此相邻帧可能发生：

    frame A: min=-0.035, max=1.056
             被误判为 [-1,1]

    frame B: min=-0.036, max=1.101
             被判为 [0,1]

错误分支相当于：

    bad = 0.5 * correct + 127.5

它会把黑色抬到约 128，并把对比度压缩一半，形成整帧发白。

已对用户提供的白闪/正常截图做过静态区域拟合：

    white = 0.476 * normal + 129.1

与错误公式高度吻合。

使用仓库中的同一模型实测：

    model/RealESRGAN_x2_dynamic.onnx

正常截图亮度 x0.90 时：

    RAW_MIN=-0.0351
    RAW_MAX=1.0566
    当前错误输出均值=174.2
    按 [0,1] 正确输出均值=93.4

这已经是修改依据。不要重新把主要原因归为：

    RTP 丢包
    H.265 解码错误
    fallback
    output slot replacement
    摄像头自动曝光

上述路径可以检查，但不得绕开已复现的数值转换缺陷。

3. 必须修复：ESRGAN 输出范围改为固定契约
======================================================================

对 backend=esrgan：

    固定按 [0,1] 输出处理
    允许模型轻微 overshoot
    先 clip 到 [0,1]
    再乘 255
    转 uint8
    RGB -> BGR

等价核心逻辑：

    array = np.clip(array, 0.0, 1.0)
    array = (array * 255.0).astype(np.uint8)

严禁继续根据单帧的：

    minimum < 0
    maximum <= 1.1

动态切换 [0,1] / [-1,1]。

要求范围模式由模型/backend 契约决定，而不是由画面内容决定。

推荐内部使用明确名称，例如：

    ZERO_TO_ONE
    MINUS_ONE_TO_ONE
    ZERO_TO_255

但不要为本项目已知的 ESRGAN 暴露一个容易误配的 CLI 参数。

7. 单元测试：必须覆盖本次闪白公式
======================================================================

更新：

    tools/test_full_frame_enhancer.py

至少增加以下测试：

A. ESRGAN [0,1] 基本转换

    0.0 -> 0
    0.25 -> 63/64
    1.0 -> 255
    RGB -> BGR 正确

B. 轻微负 overshoot

构造绝大多数值约 0.2，并放入：

    min=-0.01
    max=1.05

要求：

    负值被 clip 到 0
    0.2 仍约为 51
    黑色不能变成约 127
    整帧不能执行 (x+1)*127.5

C. 1.1 边界连续性

构造两帧仅有 RAW_MAX 差异：

    1.0999
    1.1001

要求两帧使用相同 POSTPROCESS_MODE，普通像素输出完全相同，
不得出现约 +127.5 的亮度跳变。

D. 正 overshoot

    1.05 / 1.2 -> clip 到 255

不得因为 max 超过 1.1 改变其他像素的缩放公式。

E. NaN/Inf

继续抛出 ValueError。

F. 黑帧

对真实模型可能产生少量负 overshoot 的黑色输入，后处理输出均值应接近 0，
绝不能接近 127。

如果现有测试通过 FullFrameEnhancer("none") 调用模型后处理，必须重构测试，
让测试明确指定模型输出契约；不能继续让 none backend 假扮 ESRGAN。

    模型轻微数值越界只能被稳定 clip，
    不能再让相邻帧切换色阶映射并产生白色闪烁。
