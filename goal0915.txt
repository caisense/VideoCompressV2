四、接收程序架构

数据路径：

102发送端
  → UDP 5004
  → RTP解析
  → 有界乱序缓冲
  → RO档位解析
  → RFC 7798解包
  → 完整Annex-B Access Unit
  → 档位/IDR闸门
  → Rockchip MPP HEVC硬解码
  → NV12解码帧
  → 旋转与等比例缩放
  → Weston/Wayland全屏外接屏

建议类：

1. UdpRtpReceiver
   - bind 0.0.0.0:5004
   - SO_RCVBUF 至少 1 MiB
   - 支持可配置端口
   - 记录来源地址、包长和接收时间
   - 干净响应 SIGINT/SIGTERM

2. RtpParser
   - 验证 RTP V2
   - 解析 P/X/CC/M/PT
   - 正确跳过 CSRC
   - 根据扩展 length 动态计算 payload offset
   - 正确处理 padding
   - 只接受 PT=96
   - 不得假设头长度固定为24或28字节

3. StreamProfileParser
   - 识别扩展 profile 0x524F，即 "RO"
   - 只接受 metadata version=1
   - 解析 profile、width、height、fps、generation
   - 允许理解8字节和12字节RO布局，但只激活profile 0/1/2
   - unsupported profile只记录并等待，不送入解码器
   - 非法宽高/FPS不得触发缓冲区越界或超大分配

4. RtpReorderBuffer
   - 使用16位sequence的模回绕比较
   - 有界窗口，不建立无限队列
   - 重复包丢弃
   - 窗口外旧包计为reordered/stale
   - 确认缺包后通知AccessUnitAssembler丢弃当前残缺帧
   - 目标是保护少量局域网乱序，不增加显著延迟

5. HevcRtpDepacketizer
   - Single NAL：添加 00 00 00 01
   - AP type 48：逐个读取16位NAL长度并添加start code
   - FU type 49：恢复原始HEVC两字节NAL头
   - FU sequence中断必须清空当前FU
   - 截断、零长度、越界AP/FU必须拒绝
   - 输出字节必须与PC HevcRtpDepacketizer一致

6. AccessUnitAssembler
   - 以RTP timestamp聚合
   - marker表示当前Access Unit结束
   - 记录NAL type集合
   - 识别VPS=32、SPS=33、PPS=34
   - 识别IRAP/随机访问NAL type 16..21
   - 有缺包、无marker或FU未完成时丢弃整帧

7. ProfileSwitchGate
   解码器身份至少包含：
   - generation
   - profile
   - width
   - height
   - fps

   首次启动或身份变化后：
   - 立即停止向旧解码器提交新包
   - 清空乱序/FU/AU旧状态
   - 等待新身份的完整VPS/SPS/PPS和IRAP Access Unit
   - 使用该随机访问单元启动或重建MPP解码器
   - 旧generation迟到包不得回滚当前档位

8. MppHevcDecoder
   - 使用 mpp_create
   - 使用 mpp_init(MPP_CTX_DEC, MPP_VIDEO_CodingHEVC)
   - 使用 decode_put_packet/decode_get_frame
   - 必须确认实际使用Rockchip MPP硬件解码
   - 处理info_change
   - 正确处理width、height、hor_stride、ver_stride
   - 处理errinfo、discard、EOS
   - 档位变化时优先完整重建解码上下文，避免旧stride和旧帧污染
   - 所有MppPacket、MppFrame、MppBuffer和MppCtx必须RAII释放

9. BoardDisplay
   首版使用101板已经验证的显示路径：
   - XDG_RUNTIME_DIR=/run
   - WAYLAND_DISPLAY=wayland-0
   - /run/wayland-0
   - OpenCV HighGUI运行在主线程
   - 全屏显示，不画YOLO框、mask或HUD
   - 保持宽高比，必要时黑边
   - 默认支持ccw90，允许命令行选择none
   - 正确去除MPP stride区域
   - 不得让慢显示阻塞网络接收；使用有界latest-only帧交接

九、实机验收矩阵

A. 单档冒烟测试
- low运行至少60秒
- medium运行至少60秒
- high运行至少60秒
- 每档确认外接屏有连续画面
- 日志中的profile、宽高、FPS与发送端一致
- 实际局域网正常条件下不应出现持续解码错误

B. 连续切档
- 按 low → medium → high → low 循环
- 每20秒切换一次
- 至少30次切换
- 接收程序不得重启或崩溃
- 每次应识别新generation
- 等待新VPS/SPS/PPS/IDR后恢复
- 不得出现旧尺寸帧覆盖新档画面

C. 异常测试
- 接收端晚于发送端启动
- 短暂断网后恢复
- 发送端停止并重新启动，generation重新从0开始
- 注入单包丢失、FU缺片和小范围乱序
- 发送profile 3/4测试包，接收端必须拒绝且保持稳定

D. 稳定性
- high档连续运行至少30分钟
- 记录RSS、CPU、接收/解码FPS和错误计数
- 内存不得持续线性增长
- 停止后UDP端口、MPP和显示资源必须释放
