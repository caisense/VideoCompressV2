2. 当前已确认的第一个问题：
日志把两种 age 混为一谈
======================================================================

当前进入 fallback 的条件本质是：

    LAST DISPLAYED GOOD GAN OUTPUT AGE
        >=
    fallback threshold


但日志输出的是：

    CURRENT INFERENCE RUN AGE


因此可能发生：

    last_good_age = 260ms
    fallback_threshold = 250ms

    当前新 inference 才跑：
    run_age = 84ms


日志却打印：

    GAN enhancer stalled for 84 ms


这是错误的诊断语义。


84ms并不是触发 stall 的原因。


必须修复。

13. Soft overdue 与 Hard GPU stall 必须彻底分离
======================================================================

禁止继续把：

    250ms没有新GAN输出

称为：

    GPU STALL


建立两个概念。


SOFT OVERDUE：

    视频层已经太久没有新的GAN结果

行为：

    使用最新decode帧
    Lanczos4实时显示


HARD STALL：

    当前某一次 inference 自己
    连续运行异常久

依据：

    RUN_AGE


二者不能共用一个名称。

59. Process hard restart
======================================================================

若：

    RUN_AGE > hard_stall_ms


主进程：

1.

继续 Lanczos live fallback。


2.

terminate GAN child。


3.

join with timeout。


4.

如仍alive：

kill。


5.

创建新 child。


6.

新ORT CUDA session。


7.

warmup。


8.

连续3个fresh output。


9.

恢复GAN。


整个过程中：

H265 decode不能停止。
